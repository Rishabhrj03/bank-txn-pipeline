2. Functional Requirements Audit

FR-1: File Reading & Schema Normalisation

Implemented in src/ingestion/reader.py. Reads raw CSV files with dtype=str to protect numeric identifiers with leading zeros. Auto-detects delimiters (comma and tab) and resolves custom column headers via YAML configuration.

FR-2: Deduplication Engine

Implemented in src/deduplication/deduplicator.py. Two-tier approach: Level 1 content hash (SHA-256 of business fields) catches identical rows. Level 2 ref_no key asserts bank-wide transaction reference uniqueness. Genuine repeated transactions (same amount/merchant with differing reference numbers) are protected.

FR-3: Validation Chain & Quarantine

Implemented in src/validation/rules.py and src/validation/chain.py. Implements the Chain of Responsibility pattern. Invalid records are routed to quarantine.csv with diagnostic reason tags.

FR-4: Idempotency & Safe Re-processing

Implemented in src/state/manager.py and src/pipeline/orchestrator.py. SQLite stores file content SHA-256 hashes. Already-processed files are skipped. Seeded deduplication and persistent quarantine ensure re-runs never drop or duplicate data.

FR-5: Late Correction & Backfill Sequencing

Regular daily batches are sequenced chronologically, while *late_correction* files are sequenced last. Successfully integrated 3 new transactions and eliminated 1 duplicate reference from the real feed.

FR-6: Reconciliation Summary

Produces both human-readable text (reconciliation_report.txt) and JSON (reconciliation_report.json).
